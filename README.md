# Wipöp for PrestaShop (`wipop`)

PrestaShop payment module that integrates the Wipöp gateway, allowing your
PrestaShop store to accept payments through Wipöp.

It includes card and Bizum payments, shared merchant settings,
webhook synchronization, refunds from the PrestaShop order screen, card
tokenization, optional preauthorizations, and custom recurring payment support.

## Features

- **Card payments**
  - Redirect checkout experience using Wipöp payment links.
  - Integrated COF tokenization to store cards and enable one-click charges or
    custom recurring payments.
  - Preauthorization support with order actions to capture or void.
  - Full and partial refunds from the PrestaShop order screen.
- **Bizum payments**
  - Dedicated Bizum payment option at checkout.
- **Merchant synchronization and admin tools**
  - Central configuration page in the PrestaShop Back Office with environment,
    merchant credentials, terminal, capture mode, webhook credentials, and
    enabled payment methods.
  - Credential verification that checks the merchant data and available Wipöp
    payment methods.
  - Recurring payment settings in virtual products, with monthly/yearly MIT
    charges reusing stored COF tokens.
- **Order status updates**
  - Webhook endpoint shown in the module configuration page, used to synchronize
    payment confirmations, failures, refunds, captures, reversals, and webhook
    verification events.
  - PrestaShop logs with the `[wipop]` prefix to audit relevant actions.

## Requirements

- PHP 8.1 or higher.
- PrestaShop 8.1 to 9.0.
- cURL PHP extension enabled.
- Wipöp merchant account with Sandbox and Production credentials.
- Merchant credentials:
  - Merchant ID.
  - Terminal ID.
  - Secret key.
  - Public secret key.
- HTTPS enabled in the store so Wipöp can send webhooks securely.

## Installation

### Install from ZIP

1. Download the `wipop.zip` package generated by the pipeline or your build
   system.
2. In PrestaShop Back Office go to **Modules > Module Manager**.
3. Click **Upload a module**, select the ZIP and install it.
4. Open the Wipöp module configuration page and continue with setup.

### Local development

- Follow the development guide in [development.md](development.md).

## Before you start

- Complete onboarding with Wipöp to get Sandbox and Production terminals.
- Gather all module credentials: Merchant ID, Terminal ID, Secret key and Public
  secret key.
- Ensure the store is reachable via HTTPS.
- In the Wipöp/BBVA portal, configure the webhook using the exact URL, username
  and password shown in the module configuration page.

## Quick start

1. Install the module from ZIP.
2. Open the Wipöp configuration page in the PrestaShop Back Office.
3. Fill in Merchant ID, Terminal ID, Secret key, Public secret key and the target
   environment.
4. Choose the **Preauthorizations** mode:
   - `Charge at checkout`, or
   - `Reserve the amount to charge it later`.
5. Select the Wipöp payment methods you want to offer at checkout.
6. Save the settings.
7. Click **Verify data** to validate credentials and fetch available payment
   methods.
8. Configure the webhook URL and credentials in the Wipöp/BBVA portal.
9. Place a test order in Sandbox to verify the flow. Make sure Wipöp metadata is
   stored and the webhook updates the order status.
10. Optional: mark a virtual product as recurring so that, after the first paid
    charge, the module schedules automatic MIT charges according to the selected
    frequency.

## Configuration

### Credentials and environment

Settings are stored in the PrestaShop `WIPOP_SETTINGS` configuration value.
Required fields:

- `Merchant ID`: as provided by Wipöp.
- `Secret key` / `Public secret key`: cryptographic keys used to sign requests.
- `Terminal ID`: number between 1 and 99.
- `Live mode`: disabled for Sandbox, enabled for Production.

### Manual capture / preauthorization

Select `Reserve the amount to charge it later` in **Preauthorizations** if you
want card charges to be authorized but left pending capture. When enabled:

- The order is created in the authorized Wipöp order state.
- The actions **Capture preauthorization with Wipöp** and **Void
  preauthorization with Wipöp** appear in the order action buttons.
- Capturing calls the Wipöp capture operation and updates the local payment
  attempt/order state.
- Voiding calls the Wipöp reversal operation and cancels the local
  preauthorization.
- Preauthorizations usually have a limited validity period.

With `Charge at checkout` the charge is captured immediately during checkout.

### Payment methods

The module supports card and Bizum payment methods. Choose which methods are
enabled from the Wipöp configuration page.

The module verifies merchant data against Wipöp and only shows checkout options
that are available for the configured terminal and current cart.

### Webhooks

Configure the webhook in the Wipöp/BBVA portal using the exact data shown in the
module configuration page:

- Webhook URL.
- Webhook user.
- Webhook password.

The webhook synchronizes:

- Payment status changes.
- Transaction identifiers.
- Masked card data and stored card tokens.
- Refund events.
- Manual capture metadata.
- Preauthorization capture/reversal events.
- Verification events used to mark the webhook as connected in the admin panel.

Webhook credentials can be regenerated from the module configuration page.

### Recurring products

Recurring payments are available for virtual products. When editing a virtual
product, enable **Recurring payment** and choose `Monthly` or `Yearly`.

When the first charge is marked as paid, the module:

- Verifies that the customer has a reusable stored card/COF token.
- Creates a local recurring subscription with amount, currency, period, next
  attempt date and execution sequence.
- Processes future MIT charges using the stored card token.
- Adds order/admin information for each recurring attempt.

Recurring carts have extra rules:

- They must be paid by card.
- Bizum is not available for recurring carts.
- They must contain only virtual products.
- Products in the same recurring cart must use the same period.
- Recurring charges are captured immediately even if manual capture is enabled
  for normal card payments.

Recurring payments are traffic-driven by default. The module checks for due
recurring payments when the shop receives traffic. If there are active
subscriptions ready to be renewed, Wipöp processes them in the background with
internal locking to avoid duplicate charges.

No extra setup is required for normal shops with regular traffic.

#### Low-traffic shops

If the shop receives no visits, a due renewal may be processed later, when the
next request reaches the shop.

For shops with very low traffic, or shops that need more precise renewal timing,
we recommend configuring a server cron job.

#### Optional server cron

If you have access to cron jobs in your hosting panel, you can run the Wipöp
recurring processor every 15 minutes:

```cron
*/15 * * * * cd /path/to/prestashop && /usr/bin/php bin/console wipop:recurring:process --env=prod --no-debug --limit=50 >> var/logs/wipop-recurring.log 2>&1
```

Replace `/path/to/prestashop` with the root folder of your PrestaShop
installation.

You can test the command manually with:

```bash
cd /path/to/prestashop
php bin/console wipop:recurring:process --limit=1
```

A successful output looks like:

```text
Processed 0 Wipop recurring payment(s).
```

`0` is valid: it means there were no due recurring payments at that moment.

Recurring charges can also be stopped manually from the PrestaShop order page.

Recurring charges are automatically stopped if the parent order is cancelled,
refunded or failed, or if the stored card/token data required for future charges
is no longer available.

### Refunds

Paid Wipöp orders can be refunded from the PrestaShop order page. The module
supports full and partial refunds, validates amount/currency consistency, stores
the refund event and creates the PrestaShop credit slip when possible.

Refund webhooks also synchronize refund state back into the local payment
attempt.

## Security, credentials and card data

- Merchant settings are stored in the PrestaShop configuration value
  `WIPOP_SETTINGS`.
- Webhook credentials and verification state are stored in
  `WIPOP_WEBHOOK_SETTINGS`; the webhook password is encrypted before being
  persisted.
- The module uses Wipöp hosted payment flows and does not process or store
  PAN/CVV card data in PrestaShop.
- Stored cards use Wipöp COF/source identifiers plus masked card details for
  display and future one-click or recurring charges.
- Treat database backups and Back Office access as sensitive because they can
  contain merchant credentials and payment identifiers.

## Error handling and logs

- Configuration and API failures display admin notices when possible.
- Detailed technical logs are written to PrestaShop logs with the `[wipop]`
  prefix.
